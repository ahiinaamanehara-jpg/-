# すきのスケッチ（仮称）

好きなキャラクターを自分の手で描き、創作する楽しさを見つける日本語Webアプリ。上達や完成度より、本人の選択と描く過程を大切にします。

**[アプリを開く（iPad・スマートフォン・PC共通）](https://ahiinaamanehara-jpg.github.io/-/)**

スマートフォンはいつものブラウザー、iPadはSafariで上のリンクを開いて使います。利用するだけならGitHubへのログイン・Run workflow・ターミナル操作は不要です。公開内容を更新する場合だけ、後述の公開手順を使います。作品は端末・ブラウザーごとの保存で、自動同期はしません。

## 現在の状態

M1〜M6の機能を実装し、M7「統合・スマートフォン対応」の表示改善と自動検証を行いました。推しの登録・参考画像・お題選択から、自分の手で描き、保存・振り返り・見返しまで操作できます。M7の共通操作はChromium・Firefox・WebKitで自動検証済みです。実機・OS別の最終受け入れは確認待ちです。

Androidでの利用を優先してM7の保存・再開を調整しました。iPadの使いやすさの調整は、ユーザーの希望により後で行います。保存や参考画像のPNG準備が15秒応答しない場合は入力を残してエラーを表示し、再試行できます。これは画像の準備段階の保護で、DB書込の時間制限ではありません。

保存調整後の基本操作についてユーザー確認を受領しました。今回のM7の複数ブラウザー検証は完了し、[GitHubの最終実行](https://github.com/ahiinaamanehara-jpg/-/actions/runs/39811978632)で3エンジン・計18件が成功しました。iPadの操作感の調整と実機の読み上げ等は確認待ちとして残します。

ペン・消しゴム・色・線幅・取り消し、参考画像の開閉、約1秒後の自動保存と手動保存、再開、白背景のPNG書き出しに対応しています。ホームの「続きから描く」で最後に開いた作品へ戻れます。画像の取り込みは、元の作品を残して別の作品を作ります。

画像はPNG／JPEG／WebP（10MiB・1,600万画素まで）。端末内で向きを補正し、長辺1,600px以下に縮小・再描画します。作品への取り込みは比率を保って960×960pxに収めます。推し・参考画像・テーマなしでも描けます。

キャンバスは960×960pxです。取り消しは32MiB以内（このサイズでは直前9操作）で、再開時に履歴は戻りません。保存失敗や競合では元の絵を上書きせず、画面の絵からPNG書き出し・再試行・別作品保存ができます。保存APIが使えない場合も「保存せずに落書きを試す」から一時描画と書き出しを利用できます。

「描くヒント（任意）」は表情・顔の形・簡単なポーズを独自の図解と短文で説明します。閉じると同じ絵・道具へ戻れます。「振り返る（任意）」は絵を先に保存してから1問だけ開き、自由入力・選択肢・空欄保存に対応。「この質問をスキップ」は回答を保存せず次の質問へ進み、最後まで進んでもシートを閉じません。「振り返りを終える」で閉じます。保存後の追加質問や前の作品との比較は本人が選んだときだけです。回答は後から編集・削除でき、作品画像とは分けて保存します。

ホームの作品一覧は推し・状態で絞り込み、12件ずつ表示します。詳細から再開・PNG出力・任意の振り返り・確認付き削除ができます。「途中」「ひと区切り」は自由に変更でき、どちらも描き続けられます。状態変更だけで質問は開きません。

データ管理で全件バックアップZIP（50MiBまで）を保存・追加復元できます。ZIPには参考画像・メモ・回答も含まれます。復元前に内容と件数を確認し、IDを割り当て直して追加します。同じZIPの再復元は複製になり、既存の作品・設定を上書きしません。自動同期ではありません。

現段階はテスト公開用です。M2〜M6と質問修正についてユーザーの基本確認報告を受領していますが、機種・OS・操作別詳細は未記録です。iPad相当の縦横・画面分割サイズで描画／保存を自動検証しています。iPad実機のSafari、Apple Pencil、ソフトキーボード、VoiceOver等の確認結果は[実機確認表](docs/DEVICE_CHECKLIST.md)へ記録します。

ブラウザーの文字設定を尊重する相対文字サイズを採用し、文字200%と320〜1280px幅で主要画面を操作できます。長い名前やテーマは折り返します。文字拡大の自動検証はブラウザー実機のズームや読み上げを代替しません。

React・TypeScript・Vite・Tailwind CSS、IndexedDB（idb）、ZIP作成用fflate 0.8.3の構成です。バックアップはPNGを再圧縮しない形式で、復元時のZIP検証はWeb Workerで行います。外部AI、ログイン、サーバーへの画像送信はありません。

## 開発手順

Node.js **24.19.0**、npm **11.9.0**を使用します（`.nvmrc`、`package.json`で固定）。

```sh
npm ci
npm run dev
```

```sh
npm run typecheck
npm run lint
npm run test
npm run build
```

E2Eはビルド成果物を`/workshop/`サブパスで配信して検証します。

```sh
npx playwright install chromium
npm run test:e2e
```

既存Chromiumを利用する環境では次のように実行できます。

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

5分間の連続検証は通常のE2Eと分けて実行します。

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e:long
```

Firefox／WebKitも導入できる開発環境では、共通の受け入れ・アクセシビリティテストを複数エンジンで実行できます。モバイルWebKitも実機Safariとは区別します。

```sh
npx playwright install chromium firefox webkit
npm run test:e2e:compat
```

特定のエンジンだけなら`npm run test:e2e:compat -- --project=firefox`等を指定します。未導入のエンジンは実行に失敗し、成功やスキップとして扱いません。このクラウドではブラウザーの取得先が通信制限の対象です。

[Check browser compatibility](https://github.com/ahiinaamanehara-jpg/-/actions/workflows/compatibility.yml)は、mainのアプリ・E2E・関連設定の変更時にChromium／Firefox／WebKitを別々のジョブで確認します。Actionsから手動実行もできます。1エンジンにつき全体フロー2件・アクセシビリティ3件・永続プロファイルでの保存復帰1件を実行し、自動再試行で失敗を隠しません。サイトの配信やユーザーの保存データには触れません。

WebKitの共通フローはテスト専用の永続プロファイルで実行します。隔離領域でBlob保存が拒否される場合の絵の保持とPNG退避も検証します。画像比較用のpngjsは開発専用です。

結果は各ジョブと7日間保存する`compatibility-ブラウザー名`のArtifactsで確認できます。JSON集計・通信記録・機械検査結果と、失敗時の画面・操作トレースを含みます。ローカルの互換性テストは`test-results/compat/`へ出力し、通常E2Eや5分描画の記録を消しません。モバイルWebKitはローカル設定に残し、CIの対象には含めません。最新の実行結果は[テスト記録](docs/TEST_PLAN.md)を参照してください。

E2Eには全体フロー・7種類の画面幅・Android／iPad相当の表示と入力エミュレーション・axe-coreの検査を含めます。機械検査では判断できない項目を含むため、WCAG適合や実機確認済みを意味しません。実行結果は`test-results/`、5分描画の記録は`test-results/long/`へ出力します。

クラウド環境の標準npmキャッシュが書込不可のため、`.npmrc`で`/workspace/.npm-cache`を指定しています。別環境では`npm ci --cache <書込可能なパス>`で上書きできます。

## 静的配信

`npm run build`の出力`dist/`を配信します。通常は相対アセットパスです。サブパスが決まっている場合は`npm run build -- --base=/workshop/`のように指定します。URLの画面部分はハッシュ形式なのでサーバー側のルート設定は不要です。オフライン起動は保証しません。

PagesはActionsの「Publish test site」をmainで手動実行します。公開前にlint・単体・Chromium E2E・本番ビルドを通す構成です。E2E用サブパスの成果物をそのまま公開せず、最後に通常の相対baseで再ビルドします。コードをpushするだけでは公開されません。

端末のIndexedDB v4に設定・推し・参考画像・作品画像・サムネイル・道具設定・振り返りを保存します。M6でもDB版は変更せず、v1〜v3のデータを削除せず移行します。古いタブが移行を妨げる場合は、そのタブを閉じて再読み込みします。サイトデータ削除や配信元変更でデータが消え得るため、PNGとバックアップZIPを端末へ残してください。公式画像は同梱・自動収集しません。
