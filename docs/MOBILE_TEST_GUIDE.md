# スマートフォンで画面を試す方法

現在はM5のヒント・任意の振り返りまで使えます。M4の動作確認報告を受領しました。今回はヒントの開閉、回答の保存・再表示・編集・削除・スキップを確認してください。全作品一覧・バックアップは次の工程です。

## 公開の前提

アプリのコード一式と`.github/workflows/pages.yml`がGitHubの`main`にあることが前提です。リポジトリのCode画面で`package.json`・`src`・`.github`を確認してください。READMEだけがある状態では公開できません。

GitHubにコードを保存する操作と、Pagesでサイトを公開する操作は別です。公開サイトはURLを知る人が閲覧できるため、個人情報や公式参考画像を公開用ファイルへ含めないでください。現在のコードには作品や参考画像は同梱していません。

## コード反映後にスマホで行う操作

1. Safari／ChromeなどでGitHubにログインし、`ahiinaamanehara-jpg/-`リポジトリを開きます。
2. リポジトリの **Settings → Pages** を開きます。狭い画面では横メニューの末尾や追加メニューを探します。Settingsが見当たらなければブラウザーの「デスクトップ用Webサイトを表示」を試します。リポジトリ設定を変更できる権限が必要です。
3. **Build and deployment → Source** で **GitHub Actions** を選びます。
4. リポジトリの **Actions** を開き、**Publish test site** を選びます。[ワークフロー画面を直接開く](https://github.com/ahiinaamanehara-jpg/-/actions/workflows/pages.yml)こともできます。
5. **Run workflow** でブランチが`main`であることを確認し、実行します。
6. 実行結果のbuild・deployが両方成功するまで待ちます。失敗した場合は赤い項目を開き、エラー文を確認してください。
7. **Settings → Pages** の **Visit site**、またはdeployの公開URLをタップします。表示された実際のURLを使い、推測したURLでは確認しません。

GitHubの画面表示や利用プランによって項目が異なる場合があります。非公開リポジトリでPagesが使えない場合は、リポジトリを勝手に公開へ変更せず、利用プランと別の公開先を確認してください。

## 更新後にスマホで試すこと

1. GitHubへのコード反映後、Actionsの「Publish test site」をもう一度Run workflowで実行し、build・deploy成功を待ちます。
2. 同じサイトURLを開き直します。古い画面が残る場合はまず再読み込みを試します。**サイトデータの消去は、保存した推しや準備データも消すため更新手段として使わないでください。**
3. 推しとテーマを選び「このテーマで進む」を押します。何も決めず「テーマを決めずに進む」でもキャンバスへ進めます。
4. キャンバスへ指で線を描きます。下へ少しスクロールし、色・線の太さ・消しゴム・取り消しを試します。描き始めにキャンバスが動かず、指の位置へ線が付くか確認してください。
5. 描くのを止めて「保存済み」になるのを待ちます。「途中で保存」も押せます。ページを再読み込みし、同じ絵・テーマ・道具が戻ることを確認します。**再開時に取り消し履歴は戻りません。**
6. ホームに戻り「続きから描く」で再開します。短い落書き・白紙も保存できます。縦横を回転しても絵が消えないか、キャンバス外のスクロールができるか確認します。
7. 参考画像を登録していれば、制作画面の「参考画像を見る／閉じる」を試します。絵が消えないことを確認します。
8. 「紙や他のアプリの絵を取り込む」を開いて、端末のPNG・JPEG・WebPを選びます。新しい作品として開き、加筆・保存・再読み込みを確認します。HEIC・SVGなどは変換案内が出ます。前の作品は消しませんが、全件一覧はまだないので元作品のURLとPNGも残してください。
9. 「PNGを書き出す」を押し、端末で画像を開けるか確認します。取得できなければ「画像を開く」や、表示される場合は端末共有から保存先を選びます。白背景で絵だけが入り、参考画像やボタンが含まれないことを確認してください。
10. 余裕があれば5分ほど描き、2本の指・枠外への移動で線が暴走しないか確認します。機種、OS、Safari／Chromeの版、気になった操作を報告してください。

取り消しは最大9操作です。「保存できません」と出たらページを閉じる前にPNGを書き出し、保存を再試行してください。ブラウザーのデータ削除・プライベートブラウズ・OS強制終了では保存できない／直前の線を失う場合があります。

詳しい検証状況は[テスト記録](TEST_PLAN.md)に記載しています。

## 今回のM5で試すこと

1. Actionsの「Publish test site」→「Run workflow」→mainで更新し、成功後にいつものサイトを開き直します。古いタブが保存領域の更新を止める場合は、ほかのアプリのタブを閉じて再読み込みしてください。**サイトデータは消さないでください。**
2. 前から保存していた作品を開き、絵・推し・テーマ・道具が残っていることを確認します。
3. 線を描き「描くヒント（任意）」を開きます。表情・顔の形・簡単なポーズを切り替え、閉じて絵を描き続けます。絵や取り消し履歴が消えないこと、シート内をスクロールできることを確認します。
4. 「途中で保存」だけでは質問が出ないことを確認します。「振り返る（任意）」で質問を1問開き、「この質問はスキップ」でも絵が保存されていることを確認します。
5. もう一度開き、選択肢だけ・文章だけ・空欄で保存を試します。保存後に次の質問が勝手に出ず、「もう1問（任意）」でだけ追加されることを確認します。「楽しくなかった」「特にない」も選べます。
6. 閉じて再読み込み→「振り返る（任意）」→前の回答を確認します。編集・保存、削除のキャンセル／確定を試します。回答を削除しても絵は残ります。
7. 同じ推しで画像を保存した前の作品があれば「前の作品との違いを考える（任意）」を試せます。比較は必須ではなく、「特に変わらない」「わからない」も選べます。
8. 回答を入力したまま閉じようとして破棄確認をキャンセルし、入力が残ることを確認します。キーボード表示中の保存操作、縦横回転、VoiceOver／TalkBackのラベルと保存通知も確認してください。

回答もこのブラウザー内に保存します。PNGに回答は含まれません。全件バックアップはM6で追加します。気になる点は、機種・OS・ブラウザーと操作順を添えて報告してください。

## 公開設定の検証範囲

ローカル環境で依存復元・lint・単体テスト・本番ビルドを確認する構成です。公開するのは`dist/`だけで、ソース全体やテスト結果をサイトのアセットとして配置しません。`workflow_dispatch`のみなので、コードの送信だけではこのワークフローは公開を実行しません。

ユーザーから既存のPages公開・サイト閲覧・M2〜M4の基本操作の確認報告を受領しています。M5の更新公開と実機操作は今回の更新後に確認してください。ワークフローは既定ブランチに保存されてから実行できます。公開後の更新にも同じ手動実行を使います。

公開設定の初回準備時の確認結果：lint、単体テスト15件、本番ビルド成功（過去記録）。M5の最新結果はテスト記録参照。ワークフローYAMLの構文、手動実行のみの起動条件、配信対象が`dist/`であることも確認済みです。GitHub上での実行成功を意味するものではありません。
