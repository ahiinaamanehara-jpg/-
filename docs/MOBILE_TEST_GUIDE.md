# スマートフォンで画面を試す方法

現在のアプリはM1の準備画面までです。公開しても、描画・作品保存が使えるようになるわけではありません。

## 公開の前提

アプリのコード一式と`.github/workflows/pages.yml`がGitHubの`main`にあることが前提です。リポジトリのCode画面で`package.json`・`src`・`.github`を確認してください。READMEだけがある状態では公開できません。

GitHubにコードを保存する操作と、Pagesでサイトを公開する操作は別です。公開サイトはURLを知る人が閲覧できるため、個人情報や公式参考画像を公開用ファイルへ含めないでください。現在のコードには作品や参考画像は同梱していません。

## コード反映後にスマホで行う操作

1. Safari／ChromeなどでGitHubにログインし、`ahiinaamanehara-jpg/-`リポジトリを開きます。
2. リポジトリの **Settings → Pages** を開きます。狭い画面では横メニューの末尾や追加メニューを探します。Settingsが見当たらなければブラウザーの「デスクトップ用Webサイトを表示」を試します。リポジトリ設定を変更できる権限が必要です。
3. **Build and deployment → Source** で **GitHub Actions** を選びます。
4. リポジトリの **Actions** を開き、**Publish test site** を選びます。
5. **Run workflow** でブランチが`main`であることを確認し、実行します。
6. 実行結果のbuild・deployが両方成功するまで待ちます。失敗した場合は赤い項目を開き、エラー文を確認してください。
7. **Settings → Pages** の **Visit site**、またはdeployの公開URLをタップします。表示された実際のURLを使い、推測したURLでは確認しません。

GitHubの画面表示や利用プランによって項目が異なる場合があります。非公開リポジトリでPagesが使えない場合は、リポジトリを勝手に公開へ変更せず、利用プランと別の公開先を確認してください。

## 開けた後に試すこと

- ホームから推しのノート・登録準備画面へ移動する。
- 名前とメモを入力する。保存はまだできません。
- 推しを選ばずテーマ準備・制作準備画面へ進む。
- ブラウザーの戻る・再読込を試す。
- 保存説明を開いて閉じる。画面を縦横に回転し、文字やボタンが隠れないか確認する。

詳しい検証状況は[品質検証報告](QUALITY_REPORT.md)に記載しています。

## 公開設定の検証範囲

ローカル環境で依存復元・lint・単体テスト・本番ビルドを確認する構成です。公開するのは`dist/`だけで、ソース全体やテスト結果をサイトのアセットとして配置しません。`workflow_dispatch`のみなので、コードの送信だけではこのワークフローは公開を実行しません。

GitHub上のワークフロー実行、Pages権限、公開URLへのアクセスは未確認です。ワークフローは既定ブランチに保存されてから実行できます。公開後の更新にも同じ手動実行を使います。

準備時の確認結果：lint、単体テスト15件、本番ビルド成功。ワークフローYAMLの構文、手動実行のみの起動条件、配信対象が`dist/`であることも確認済みです。GitHub上での実行成功を意味するものではありません。
