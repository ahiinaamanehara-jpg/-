# 製品仕様書

## 目的と設計原則

初心者が好きなキャラクターを自分らしく描き、描く過程を楽しめるよう支援する。主な利用者は、これからイラストを始めたい人、白紙や技量への不安がある人。スマートフォン縦画面を中心にPCでも利用できる。

正確さ、上手さ、制作量、継続日数を評価しない。題材・表現・終了時点は本人が決める。短い落書き、未完成、楽しくなかった体験も受け入れる。講座・振り返りは任意で、描画の条件にしない。

## 初期版の機能

| 機能 | 仕様 |
| --- | --- |
| 推し登録 | 名前、参考画像、好きな特徴・描きたい部分のメモ。複数登録・編集・切替・削除 |
| テーマ | 表情／衣装・小物／ポーズ・場面／自由入力。候補最大3件、再提案・編集・スキップ可能 |
| 描画 | ペン、消しゴム、色、線幅、取り消し、保存。タッチ・マウス対応。途中保存と再開 |
| 画像取込 | 紙・他アプリの絵を作品として取り込み、続きを描く。参考画像登録とは区別 |
| ヒント | 表情、顔の形、簡単なポーズ。独自の汎用図解と短文。いつでも開閉 |
| 振り返り | 一度に1問。自由入力・選択肢・スキップ。希望した場合だけ追加質問 |
| ギャラリー | 推し別絞込、途中作品、テーマ・制作日・回答の確認、再開、PNG書き出し |
| データ管理 | 保存状態・失敗表示、全データバックアップ・追加復元・削除、容量の説明 |

ログイン、課金、SNS、ランキング、連続報酬、AI生成・採点・外部AI API、公式画像収集、不要な通知は作らない。複雑なレイヤー、変形、筆圧、クラウド同期、オフラインでのアプリ起動保証も初期版の対象外。

## 体験と質問

「推しを選ぶ→テーマを決める→描く／取り込む→保存→任意の振り返り→見返す」が基本。推し未選択・テーマ空欄でも自由な落書きを始められる。作品状態は「途中」「ひと区切り」で、どちらも再開・変更可能。

お題は静的な日本語データから選ぶ。「笑顔」「髪飾りをひとつ」「好きな飲み物を持つ」など顔・上半身だけでも成立するものを中心とする。難易度や正解、進級条件は設けない。キャラクターの公式設定を推測しない。

保存成功後の通常の初問は「今回、描いていて一番楽しかったのは？」、途中保存時に本人が振り返りを開いた場合は「今回はどんなイラストが描けた？」を暫定とする。回答せず終了しても作品は保存済み。「楽しくなかった」「特にない」と自由入力を認める。回答への返答は評価せず「保存しました」とする。

「もう1問」を選んだ場合、気に入ったところ、表現したかった魅力、工夫、発見、次に描きたい姿から未表示の質問を出す。「前回と比べて変わったところ」は同じ推しの過去作品があり、本人が比較質問を選んだ場合のみ表示する。良い変化を前提にしない。回答は後日編集・削除できる。

## 技術構成

React・TypeScript・Vite・Tailwind CSSの静的SPA。Canvas 2DとPointer Eventsで描画し、IndexedDBと薄いラッパーidbで永続化する。小規模なローカル状態・Contextから始め、重い状態管理や描画フレームワーク、バックエンドは導入しない。静的ホストで再読込できるハッシュルーティングを採用予定。

Vitest・Testing Library・Playwrightを検証に使用予定。実装時点の互換性ある安定版とNode.js LTSを固定する。外部フォント・解析・CDN依存を設けず、画像・入力・回答を送信しない。配信アセットの取得やホスト側アクセスログは、ユーザー画像の送信とは区別して説明する。

対象はiOS Safari／Android Chromeの直近2メジャー版、PCのChrome・Edge・Firefox・Safariの現行安定版を暫定とする。IndexedDB・Canvas・画像デコードを機能検出する。

## データモデル

| データ | 主な項目 |
| --- | --- |
| Character | UUID、名前（必須100文字まで）、メモ（2,000文字まで）、任意のreferenceAssetId、作成・更新日時 |
| Artwork | UUID、任意のcharacterId、テーマ（500文字まで）・カテゴリ、状態、canvasAssetId、thumbnailAssetId、幅・高さ、作成・更新日時、revision |
| Asset | UUID、種別、Blob、MIME、サイズ、幅・高さ |
| Reflection | UUID、artworkId、questionId、選択回答／自由回答（2,000文字まで）、作成・更新日時 |
| Settings | 最後に開いた作品ID、道具設定、形式バージョン |

日時はUTCのISO形式で保存し、端末のローカル時間で表示する。制作日は作成日、更新日は別表示。DBはバージョン管理し、移行失敗で既存データを削除しない。

## 描画と保存

キャンバスは暫定960×960px、表示サイズと保存解像度を分離する。ペンは単色線、消しゴムは透明化。画面・PNG出力は白背景。参考画像はキャンバス外の参照用として表示し、出力へ混ぜない。

1枚のビットマップを保存する。取り消しは現セッションのみ、最大20操作かつ32MiBのメモリー予算以内を暫定とし、古い履歴から破棄する。消しゴム・取込も対象。再開時は絵と道具設定を復元し、以前の取り消し履歴は戻らないことを説明する。

ストローク終了・編集停止から約1秒で自動保存、明示的保存は即時実行。「保存中／保存済み／保存できません」を区別する。画像・サムネイル・作品は同一トランザクションで更新し、非同期保存が新しい状態を巻き戻さないようrevisionを確認する。複数タブの競合は上書きせず、再読込か別作品保存を選ぶ。

アプリ内の離脱時は保存を待ち、失敗時は留まる／破棄を選べる。終了イベントだけに依存しない。OSの強制終了直前の未保存分までは保証しない。保存失敗時はメモリー上の絵を保持してPNG書出・再試行を案内する。DB利用不可では一時描画・書出に限定し、再読込で失うことを示す。

## 画像・容量・バックアップ

PNG・JPEG・WebPを受け付け、拡張子だけでなくMIME・実際のデコードを検証する。SVG・GIF・HEICは対象外として変換を案内する。参考画像は推し1人につき1枚を暫定とする。

暫定上限は1ファイル10MiB・16メガピクセル、保存時の長辺1,600px。ヘッダーで寸法を事前確認し、デコード後も検証する。向きを補正し再描画してメタデータを引き継がず保存する。元ファイルを保持しないことと縮小を事前説明する。取込作品は比率を維持して収める。描画済み作品への取込は別作品として作成し、既存絵を上書きしない。

PNG出力には絵だけを含める。端末のダウンロードに制約がある場合は共有・画像を開く代替導線を用意し実機確認する。

Storage APIが使えれば容量目安を表示するが、保存可能量の保証にしない。永続ストレージ要求は対応環境で任意操作として提供する。プライベートブラウズ、サイトデータ削除、端末変更、オリジン変更で失われ得ることを説明する。

全データバックアップは形式バージョン付きmanifestと画像を含むZIPを暫定形式とする。PNGとは異なり、参考画像・メモ・回答を含むことを示す。復元は検証・件数プレビュー後、IDを再割当して追加し、既存作品を上書きしない。暫定上限ZIP50MiB・展開後100MiB・画像1,000件。サイズ、参照整合性、形式版、展開容量を確認し、不正な内容は保存前に拒否する。

推し削除では作品を残して未分類へ移す。作品削除では関連画像・回答をトランザクションで削除する。全消去は別操作とし、対象と復元不能を確認する。

## UI・権利・プライバシー

日本語、本文16px以上、操作領域原則44×44 CSS px以上。通常文字4.5:1以上などWCAG AAのコントラストに配慮し、色だけで状態を伝えない。ラベル、フォーカス、ダイアログのフォーカス管理・復帰を用意する。周囲のスクロールとブラウザー拡大を禁止しない。

キーボードで登録・道具・保存・取込・ギャラリー・振り返りを操作可能にする。自由描画自体はポインターが必要という制約を明示し、画像取込からも参加できるようにする。

参考画像はユーザーが用意し、明示的な同意なく外部送信しない。公式画像を同梱・自動収集せず、教材は独自の汎用図解とする。商用利用や再配布を前提とせず、権利者のガイドライン確認を案内する。

- 対応OSの最低版・実機の入手範囲：M1で確認。不足する実機検証を完了扱いにしない。
- 参考画像1枚・表示領域：M2／M4で操作確認して確定。
- キャンバス比率、画像上限、取消回数・予算：M4で低性能端末の計測に基づき確定。
- ZIPライブラリーとバックアップ上限：M6で保守状況・容量・性能を評価して固定。
- 配信先：GitHub Pagesをテスト用に使用。オリジン変更時はデータ移行が必要。

未回答でも上記の暫定案で段階開発できる。決定時に理由と影響を更新する。


## M2で確定した仕様

- 参考画像は推し1件につき1枚。登録時は任意。画像なしでも名前だけで保存できる。
- 推しの一覧カードで選択中を表示し、選択を端末内に保持する。「推しを選ばずに進む」では選択を解除する。テーマ準備画面に選択中の名前を表示するが、お題選択はM3の範囲。
- 推しの保存は明示操作。名前は前後空白を除き100文字、メモは2,000文字まで（ブラウザー入力のUTF-16長で統一）。画像の処理中と保存処理中は保存を重複実行しない。
- 編集中にリンク・戻るで離れる場合は未保存確認、保存処理中は完了まで画面に留める。タブ・OSの強制終了で未保存入力は失われ得る。
- DB v2へ非破壊移行してcharacters／assetsを追加。推しと画像の更新・削除は原子的に行い、編集競合をrevisionで検出する。
- 参照画像が欠落・不正でも推しの名前・メモを開き、画像を明示的に外す／選び直すことで回復できる。既存データの自動消去は行わない。
- 現在は作品データがないため、推し削除は推し・参考画像・選択状態の整理のみ。作品ストア追加時に「作品を未分類へ残す」を同一トランザクションへ追加する。


## M3で確定した仕様

- お題は表情・衣装／小物・ポーズ／場面の各6件、計18件の独自の静的日本語データ。一度に最大3件、再提案では直前の候補を除く。難易度・正解・達成条件は付けない。
- 自由入力では候補を出さず、どのカテゴリでもテーマ欄を自由に編集できる。カテゴリ切替・再提案で入力済みテーマを消さない。候補の自動選択はしない。
- テーマは500文字まで（UTF-16長）。前後空白を除いて保存し、空欄でも進める。「テーマを決めずに進む」は入力済みテーマを採用せず空欄で準備データを作る。保存失敗時は元の入力を保持。
- キャラクターの選択は今回の準備データに適用。初期値はM2の選択中の推し。別タブで推しが追加・改名・削除されたらフォーカス復帰時に選択肢を更新し、入力テーマを保持する。削除済みの選択を黙って別の推しへ変更しない。
- 「このテーマで進む」で推し・テーマ・カテゴリ・日時・revision・途中状態を持つ準備データを作り、`#/draw/:id`へ移動する。M3では画像はなく、サイズ960×960のメタデータだけ。実際のキャンバスはM4。
- 「別のテーマで準備する」は別データを作る導線。既存準備を上書きしない。ホームの再開先は、最後に正常に開いた準備。再開位置の書込に失敗しても、既存準備の表示は行い注意を示す。
- DB v3にartworksを追加。v1／v2の設定・推し・画像を非破壊で移行する。準備データと再開先は同一トランザクションで作成し、失敗時に片方だけ残さない。
- 推しの削除は、関連する準備データを自由な落書き（未分類）へ移し、テーマや準備データ本体を保持する。元の作成日時を保持し、更新日時・revisionを更新する。
- 未保存のテーマ・今回の推し選択がある場合は画面移動で確認する。保存操作前の入力はOS強制終了から復元できるとは限らない。
