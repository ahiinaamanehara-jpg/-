# 製品仕様書

## 目的と設計原則

初心者が好きなキャラクターを自分らしく描き、描く過程を楽しめるよう支援する。主な利用者は、これからイラストを始めたい人、白紙や技量への不安がある人。スマートフォン縦画面を中心にPCでも利用できる。

正確さ、上手さ、制作量、継続日数を評価しない。題材・表現・終了時点は本人が決める。短い落書き、未完成、楽しくなかった体験も受け入れる。講座・振り返りは任意で、描画の条件にしない。

## 初期版の機能

| 機能 | 仕様 |
| --- | --- |
| 推し登録 | 名前、参考画像、好きな特徴・描きたい部分のメモ。複数登録・編集・切替・削除 |
| テーマ | 表情／衣装・小物／ポーズ・場面／自由入力。候補最大3件、再提案・編集・スキップ可能 |
| 描画 | ペン、消しゴム、色、線幅、取り消し、保存。タッチ・マウス対応。途中保存と再開 |
| 画像取込 | 紙・他アプリの絵を作品として取り込み、続きを描く。参考画像登録とは区別 |
| ヒント | 表情、顔の形、簡単なポーズ。独自の汎用図解と短文。いつでも開閉 |
| 振り返り | 一度に1問。自由入力・選択肢・スキップ。希望した場合だけ追加質問 |
| ギャラリー | 推し別絞込、途中作品、テーマ・制作日・回答の確認、再開、PNG書き出し |
| データ管理 | 保存状態・失敗表示、全データバックアップ・追加復元・削除、容量の説明 |

ログイン、課金、SNS、ランキング、連続報酬、AI生成・採点・外部AI API、公式画像収集、不要な通知は作らない。複雑なレイヤー、変形、筆圧、クラウド同期、オフラインでのアプリ起動保証も初期版の対象外。

## 体験と質問

「推しを選ぶ→テーマを決める→描く／取り込む→保存→任意の振り返り→見返す」が基本。推し未選択・テーマ空欄でも自由な落書きを始められる。作品状態は「途中」「ひと区切り」で、どちらも再開・変更可能。

お題は静的な日本語データから選ぶ。「笑顔」「髪飾りをひとつ」「好きな飲み物を持つ」など顔・上半身だけでも成立するものを中心とする。難易度や正解、進級条件は設けない。キャラクターの公式設定を推測しない。

本人が振り返りを開いた場合、「ひと区切り」の初問は「今回、描いていて一番楽しかったのは？」、「途中」の初問は「今回はどんなイラストが描けた？」とする。保存や状態変更だけでは質問を開かない。回答せず終了しても作品は保存済み。「楽しくなかった」「特にない」と自由入力を認める。回答への返答は評価せず「保存しました」とする。

「もう1問」を選んだ場合、気に入ったところ、表現したかった魅力、工夫、発見、次に描きたい姿から未表示の質問を出す。「前回と比べて変わったところ」は同じ推しの過去作品があり、本人が比較質問を選んだ場合のみ表示する。良い変化を前提にしない。回答は後日編集・削除できる。

「この質問をスキップ」は質問への回答を保存せず次の未表示の通常質問へ進む。未保存入力があれば破棄を確認し、キャンセルなら保持する。既に保存された回答をスキップで削除しない。通常質問が尽きたら終了を案内して回答一覧へ戻り、シートは開いたままとする。比較質問を自動で出したり、同じ質問を繰り返したりしない。「振り返りを終える」でシートを閉じる。

## 技術構成

React・TypeScript・Vite・Tailwind CSSの静的SPA。Canvas 2DとPointer Eventsで描画し、IndexedDBと薄いラッパーidbで永続化する。小規模なローカル状態・Contextから始め、重い状態管理や描画フレームワーク、バックエンドは導入しない。静的ホストで再読込できるハッシュルーティングを採用予定。

Vitest・Testing Library・Playwrightを検証に使用予定。実装時点の互換性ある安定版とNode.js LTSを固定する。外部フォント・解析・CDN依存を設けず、画像・入力・回答を送信しない。配信アセットの取得やホスト側アクセスログは、ユーザー画像の送信とは区別して説明する。

対象はiOS／iPadOS SafariとAndroid Chromeの直近2メジャー版、PCのChrome・Edge・Firefox・Safariの現行安定版を暫定とする。iPadは縦横表示と画面分割も確認対象とする。IndexedDB・Canvas・画像デコードを機能検出する。対象と検証済みを区別し、実機・ブラウザー別の確認状況を実機確認表に記録する。

## データモデル

| データ | 主な項目 |
| --- | --- |
| Character | UUID、名前（必須100文字まで）、メモ（2,000文字まで）、任意のreferenceAssetId、作成・更新日時 |
| Artwork | UUID、任意のcharacterId、テーマ（500文字まで）・カテゴリ、状態、canvasAssetId、thumbnailAssetId、幅・高さ、作成・更新日時、revision、作品ごとの道具設定 |
| Asset | UUID、種別、Blob、MIME、サイズ、幅・高さ |
| Reflection | UUID、artworkId、questionId、選択回答／自由回答（2,000文字まで）、任意の比較作品ID、作成・更新日時、独立したrevision |
| Settings | 最後に開いた作品ID、選択中の推しID、形式バージョン |

日時はUTCのISO形式で保存し、端末のローカル時間で表示する。制作日は作成日、更新日は別表示。DBはバージョン管理し、移行失敗で既存データを削除しない。

## 描画と保存

キャンバスは暫定960×960px、表示サイズと保存解像度を分離する。ペンは単色線、消しゴムは透明化。画面・PNG出力は白背景。参考画像はキャンバス外の参照用として表示し、出力へ混ぜない。

描画の道具はキャンバスのすぐ下に配置する。通常文字の320／360px幅ではペン・消しゴム・取り消しを横に並べ、色・線幅・途中保存へ進める。文字を拡大した場合は道具を折り返し、各44px以上の操作領域を保つ。操作説明は保存・PNG書出の後に置き、キャンバスの説明としても関連付ける。固定表示で絵を覆わず、キャンバス外のスクロールを維持する。

1枚のビットマップを保存する。取り消しは現セッションのみ、最大20操作かつ32MiBのメモリー予算以内（960pxでは最大9操作）を暫定とし、古い履歴から破棄する。消しゴム・取込も対象。再開時は絵と道具設定を復元し、以前の取り消し履歴は戻らないことを説明する。

ストローク終了・編集停止から約1秒で自動保存、短い編集を繰り返す間も約5秒を目安に保存を試みる。ストローク中は終了後に保存する。明示的保存は即時実行。「保存中／保存済み／保存できません」を区別する。画像・サムネイル・作品は同一トランザクションで更新し、非同期保存が新しい状態を巻き戻さないようrevisionを確認する。複数タブの競合は上書きせず、再読込か別作品保存を選ぶ。

アプリ内の離脱時は保存を待ち、失敗時は留まる／破棄を選べる。終了イベントだけに依存しない。OSの強制終了直前の未保存分までは保証しない。保存失敗時はメモリー上の絵を保持してPNG書出・再試行を案内する。DB利用不可では一時描画・書出に限定し、再読込で失うことを示す。

PNG生成の完了通知が15秒戻らない場合は、DBへ書き込む前に失敗として扱う。画面の絵・フォーム入力・既存の保存を保持し、保存／画像選択を再試行できる。失敗した処理の遅い通知では保存を再開しない。作品・サムネイル・参考画像・PNG出力で共通の保護を使う。DBトランザクションの時間制限は追加しない。15秒は低速な実機での確認後に見直せる暫定値。保存状態が変わっても状態表示の枠の高さを保ち、描き始めにキャンバスを動かさない。

## 画像・容量・バックアップ

PNG・JPEG・WebPを受け付け、拡張子だけでなくMIME・実際のデコードを検証する。SVG・GIF・HEICは対象外として変換を案内する。参考画像は推し1人につき1枚を暫定とする。

暫定上限は1ファイル10MiB・16メガピクセル、保存時の長辺1,600px。ヘッダーで寸法を事前確認し、デコード後も検証する。向きを補正し再描画してメタデータを引き継がず保存する。元ファイルを保持しないことと縮小を事前説明する。取込作品は比率を維持して収める。描画済み作品への取込は別作品として作成し、既存絵を上書きしない。

PNG出力には絵だけを含める。端末のダウンロードに制約がある場合は共有・画像を開く代替導線を用意し実機確認する。

Storage APIが使えれば容量目安を表示するが、保存可能量の保証にしない。永続ストレージ要求は対応環境で任意操作として提供する。プライベートブラウズ、サイトデータ削除、端末変更、オリジン変更で失われ得ることを説明する。

全データバックアップは形式バージョン付きmanifestと画像を含むZIPを暫定形式とする。PNGとは異なり、参考画像・メモ・回答を含むことを示す。復元は検証・件数プレビュー後、IDを再割当して追加し、既存作品を上書きしない。暫定上限ZIP50MiB・展開後100MiB・画像1,000件。サイズ、参照整合性、形式版、展開容量を確認し、不正な内容は保存前に拒否する。

推し削除では作品を残して未分類へ移す。作品削除では関連画像・回答をトランザクションで削除する。全消去は別操作とし、対象と復元不能を確認する。

## UI・権利・プライバシー

日本語、本文16px以上、操作領域原則44×44 CSS px以上。通常文字4.5:1以上などWCAG AAのコントラストに配慮し、色だけで状態を伝えない。ラベル、フォーカス、ダイアログのフォーカス管理・復帰を用意する。周囲のスクロールとブラウザー拡大を禁止しない。

キーボードで登録・道具・保存・取込・ギャラリー・振り返りを操作可能にする。自由描画自体はポインターが必要という制約を明示し、画像取込からも参加できるようにする。

参考画像はユーザーが用意し、明示的な同意なく外部送信しない。公式画像を同梱・自動収集せず、教材は独自の汎用図解とする。商用利用や再配布を前提とせず、権利者のガイドライン確認を案内する。

## 暫定判断・未確定事項

- 名称・配色・アイコン：M1では仮称「すきのスケッチ」、暖色・システムフォント・文字記号を採用。正式名称は未確定。
- 対応OSの最低版・実機の入手範囲：M1で確認。不足する実機検証を完了扱いにしない。
- 参考画像1枚・表示領域：M2／M4で操作確認して確定。
- キャンバス比率、画像上限、取消回数・予算：M4で低性能端末の計測に基づき確定。
- ZIP形式・ライブラリー：M6でfflate 0.8.3と再圧縮しない形式を採用。50MiB上限は実機のメモリー・応答性をM7でも確認し、必要なら下げる。
- 配信先：GitHub Pagesをテスト用に使用。オリジン変更時はデータ移行が必要。

未回答でも上記の暫定案で段階開発できる。決定時に理由と影響を更新する。


## M2で確定した仕様

- 参考画像は推し1件につき1枚。登録時は任意。画像なしでも名前だけで保存できる。
- 推しの一覧カードで選択中を表示し、選択を端末内に保持する。「推しを選ばずに進む」では選択を解除する。テーマ準備画面に選択中の名前を表示するが、お題選択はM3の範囲。
- 推しの保存は明示操作。名前は前後空白を除き100文字、メモは2,000文字まで（ブラウザー入力のUTF-16長で統一）。画像の処理中と保存処理中は保存を重複実行しない。
- 編集中にリンク・戻るで離れる場合は未保存確認、保存処理中は完了まで画面に留める。タブ・OSの強制終了で未保存入力は失われ得る。
- DB v2へ非破壊移行してcharacters／assetsを追加。推しと画像の更新・削除は原子的に行い、編集競合をrevisionで検出する。
- 参照画像が欠落・不正でも推しの名前・メモを開き、画像を明示的に外す／選び直すことで回復できる。既存データの自動消去は行わない。
- 現在は作品データがないため、推し削除は推し・参考画像・選択状態の整理のみ。作品ストア追加時に「作品を未分類へ残す」を同一トランザクションへ追加する。


## M3で確定した仕様

- お題は表情・衣装／小物・ポーズ／場面の各6件、計18件の独自の静的日本語データ。一度に最大3件、再提案では直前の候補を除く。難易度・正解・達成条件は付けない。
- 自由入力では候補を出さず、どのカテゴリでもテーマ欄を自由に編集できる。カテゴリ切替・再提案で入力済みテーマを消さない。候補の自動選択はしない。
- テーマは500文字まで（UTF-16長）。前後空白を除いて保存し、空欄でも進める。「テーマを決めずに進む」は入力済みテーマを採用せず空欄で準備データを作る。保存失敗時は元の入力を保持。
- キャラクターの選択は今回の準備データに適用。初期値はM2の選択中の推し。別タブで推しが追加・改名・削除されたらフォーカス復帰時に選択肢を更新し、入力テーマを保持する。削除済みの選択を黙って別の推しへ変更しない。
- 「このテーマで進む」で推し・テーマ・カテゴリ・日時・revision・途中状態を持つ準備データを作り、`#/draw/:id`へ移動する。M3では画像はなく、サイズ960×960のメタデータだけ。実際のキャンバスはM4。
- 「別のテーマで準備する」は別データを作る導線。既存準備を上書きしない。ホームの再開先は、最後に正常に開いた準備。再開位置の書込に失敗しても、既存準備の表示は行い注意を示す。
- DB v3にartworksを追加。v1／v2の設定・推し・画像を非破壊で移行する。準備データと再開先は同一トランザクションで作成し、失敗時に片方だけ残さない。
- 推しの削除は、関連する準備データを自由な落書き（未分類）へ移し、テーマや準備データ本体を保持する。元の作成日時を保持し、更新日時・revisionを更新する。
- 未保存のテーマ・今回の推し選択がある場合は画面移動で確認する。保存操作前の入力はOS強制終了から復元できるとは限らない。


## M4で具体化した仕様

- 制作URLは従来の`#/draw/:id`を引き継ぎ、画像なしのM3データも白紙から編集できる。ホームは最後に開いた作品への「続きから描く」を提供。全件一覧と作品の削除はM6。
- 960×960pxを採用し、表示のみCSSで縮小。ペン色は任意のRGB、幅1〜40px。筆圧・多層編集は対象外。単一ポインターを追跡し、2本目の指を無視、取消イベントではそこまでの線を残して終了する。
- 取消は32MiB以内のビットマップ履歴。960pxでは9操作。取込直後の同じセッションでは1回で取込を白紙へ戻せる。再読込後の履歴復元はしない。
- DB v3の既存artworksに画像・サムネイルのIDと道具設定を任意属性として追加。新規ストアは不要のためDB版は変更しない。旧データを全件書き換えず、画像を保存した作品から属性が付く。
- 保存成功はIndexedDBトランザクションの完了後のみ表示。保存中も描画でき、追加分を次に保存する。別タブの更新・推し削除によるrevision変更は競合として止める。今の画像を別作品へ救済保存できる。
- 保存画像が欠落・破損・別種のデータを参照している場合は、自動で消去・白紙化しない。画像とサムネイルの参照が片方だけの場合も編集を止める。
- 画像取込は常に元の作品を残し、同じ推し・テーマを持つ別作品を作る。画像を960px正方形の中央へ比率を保って配置し、余白は透明。取込失敗は元の作品に影響しない。
- 画面・192pxサムネイル・PNG出力は白背景。作品ビットマップは透明を保持する。参考画像は開閉式のキャンバス外表示で、作品保存やPNG出力には合成しない。
- 保存APIを利用できない場合は、ホームの「保存せずに落書きを試す」→`#/draw/new`で一時描画・PNG書き出しが可能。端末内保存・取込は無効。再読込で消えることを表示する。
- PNGは端末へのダウンロード／画像を開く導線を提供する。対応環境の端末共有は利用者の明示操作でのみ呼び出し、アプリから画像を送信しない。OSの保存先・共有先は本人が選ぶ。
- 実機の入力遅延・手のひら誤操作・5分描画・OSの画像取得は確認待ち。ブラウザー自動操作の結果から低性能端末対応を確定しない。960pxと履歴予算は実機結果で見直せる暫定値を維持する。


## M5で具体化した仕様

- ヒントは「表情」「顔の形」「簡単なポーズ」の3種類。独自のSVG図解と短文で、特定作品の画像や設定に依存しない。講座・進級・描画の代行・受講記録は設けない。
- ヒントは保存APIを利用できない一時描画でも使える。開閉でビットマップ・道具・取消履歴を初期化せず、Escapeや戻るボタンで制作へ復帰する。
- 振り返りは利用者が「振り返る（任意）」を押した場合だけ開く。先に作品画像の保存を完了する。保存に失敗した場合は回答画面を開かず、今の絵と書き出し・再試行の導線を保つ。
- M5では作品状態は引き続き「途中」。初問は「今回はどんなイラストが描けた？」。M6の「ひと区切り」導線とは分け、状態変更は先行実装しない。自動／手動保存だけでは質問を出さない。
- 新しい質問は一度に1問。「もう1問（任意）」は保存済み・今回表示済みの通常質問を除いて選ぶ。推しなしの場合は推しの魅力を尋ねない。比較質問は通常の追加質問に混ぜない。
- 3個の短い選択肢と自由入力2,000文字を併用可能。選択をもう一度押すと解除。初期選択なし。空欄の保存・スキップ・否定的な回答を認める。当初の「スキップで閉じる」はユーザー確認後に変更し、上記の「次の質問へ進む」と終了を分けた。
- 保存後は質問を自動追加せず、保存済みの回答を表示する。回答の編集・確認付き削除は同じ任意シートから可能。絵を再開した後でも回答を編集できる。
- 比較候補は、同じ推しの別作品で、現在の作品より作成日時が前・画像保存済みのもの。本人が比較を選んだ場合だけ候補と前の絵を表示する。上達を前提にせず「特に変わらない」「わからない」を用意する。過去作品・推しがなくても通常の振り返りは利用できる。
- DB v4でreflectionsを非破壊追加。作品索引と作品・質問の一意索引を設け、1作品につき1問1回答を後から編集する。回答保存はトランザクション完了後に成功表示し、回答独自のrevisionで競合を検出する。画像や作品のrevisionは変更しない。
- 不正な移行元・回答・索引は、自動で消去・初期化しない。別タブが移行を妨げる場合は閉じて再試行する。未保存の回答を閉じる場合は破棄を確認し、失敗時は入力を保持する。OS強制終了前の未保存回答は保証しない。
- 回答の全件バックアップ・別端末移行、ギャラリーからの回答閲覧はM6。M5のスマートフォン実機・読み上げ・ソフトキーボードは確認待ち。

## M6で具体化した仕様

- ホームで更新日時順の一覧を12件ずつ表示する。推し・未分類・状態で絞り込める。表示付近の192pxサムネイルだけを読み、原寸画像を一覧へまとめて読み込まない。読み込めない作品・推しは件数を案内し、元データを残して正常な作品を表示する。
- 詳細は絵・推しのメモ・テーマ・制作日・更新日・状態・振り返り件数を表示し、再開・白背景PNG出力・任意の振り返り・削除を提供する。状態変更はrevisionを確認し、「ひと区切り」からも描き続けられる。描画で状態を勝手に戻さない。
- 作品削除は作品名を示して確認する。作品・専用画像・その回答・該当する再開先を同一トランザクションで削除し、他の作品・推し・参考画像を残す。他作品から比較されていた場合は、その回答を削除せず比較先削除の印を付ける。不正な共有参照がある画像も他のデータを守るため残す。
- 別タブ競合時は最新の保存を明示的に読み直せる。別タブで元作品が削除されても、編集中の絵を新しい作品へ救済保存できる。救済時に既に削除された推しへの参照は付けない。
- バックアップは`manifest.json`（`format: suki-sketch`、`version: 1`）と`assets/連番.png`。fflate 0.8.3（MIT）を固定し、圧縮済みのPNGはZIP内で再圧縮しない。読み込みはこのアプリが出すSTORE方式のみを対象とし、一般のZIP・再圧縮されたZIP・ZIP64・暗号化・未知ファイル・危険なパスを拒否する。
- ZIP50MiB・展開後100MiB・画像1,000件・manifest 8MiB、各種類のデータ10,000件・設定1,000件を上限とする。STORE方式なので実際の展開量もZIPサイズ以内。ヘッダー・実長・CRC・形式版・一意性・画像寸法／実デコード・参照関係を保存前に検証する。ZIPの解析はWeb Worker、書き出しは小分け処理を使う。
- 検証後に件数・日時をプレビューし、明示操作で全IDを再割当して追加する。既存作品・既存設定を優先して保持する。同じZIPを再度追加すると複製になる。検証・追加失敗は既存データを変えず、追加途中の失敗は全追加分をロールバックする。
- 全消去は確認シートで「全データを削除」と入力したときだけ実行する。5ストアを一括消去し、失敗時はすべて元に戻す。バックアップ・復元・消去の処理中はアプリ内移動を止める。OSの強制終了やブラウザーによるデータ消去自体を防ぐ保証はない。
- IndexedDBはv4を維持する。状態の許容値と任意の比較先削除フラグを拡張し、既存レコードの一括書換・ストア削除は行わない。実機のZIP取得・ファイル選択・容量不足・読み上げ・応答性はM7を含む確認対象として残す。

## M7の表示・検証方針

- 本文・見出し・ボタン・補助文の文字サイズはブラウザーの基本文字サイズに追従する。見出しの段階的な大きさは画面幅で切り替え、文字拡大を固定pxで打ち消さない。長い英数字を含む推し名・テーマ・メモを折り返す。
- 320／375／390／768／810／1024／1280px幅と文字200%を自動確認する。iPad相当の768×1024・810×1080と各横向き、375pxの狭い表示幅も確認する。表示幅・タッチのエミュレーションをiPad実機の検証と呼ばない。
- 既存の一連の操作・保存保護・外部通信・キーボード・フォーカス・axe-core検査・5分描画を検証する。axe-coreは開発専用で本番アセットに同梱しない。自動判定不能、実機の読み上げ、OSのファイル保存は別途確認する。
- M7で新しい大型機能・保存形式変更・DB移行は行わない。IndexedDB v4とバックアップ形式v1を維持する。実機受け入れが残る間はテスト公開を維持し、すべての対象端末への対応保証を確定しない。


## M7の共通ブラウザー検証で確定した条件

- 画像保持はPNGの圧縮表現ではなく画素で確認する。alphaと不透明色は一致を要求し、同じalphaの半透明色に限り、PNG復元時の丸めとして白背景で最大1段階（1/255）を区別する。保存・バックアップのBlobのSHA-256確認は別途維持する。
- 通常利用のWebKit自動検証はテスト専用の永続プロファイルを使う。Linux WebKitの隔離領域でBlob保存を拒否する条件では、失敗表示・現在の絵の保持・PNG退避を確認する。実Safariやすべてのプライベートモードの動作保証とはしない。
- 共通エンジンの自動確認と、OSの写真選択・保存先・読み上げ・iPadの操作感等の実機確認を分ける。iPadの調整はユーザーの指示で後日とする。
