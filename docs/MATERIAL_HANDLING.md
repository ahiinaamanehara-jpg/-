# 教材をアプリ外で共有しないための整理

作成日：2026-10-29。方針更新：2026-10-30。照合対象：`5de4ff8`。**対象範囲はユーザー回答を反映した設計。制限は未実装。**

## 1. 指定された方針と残る判断

**指定**：「基本的に、ユーザーが教材として使用するものをアプリ外で共有しないようにしたい」。

**指定・2026-10-30の回答で確定（D10）**：「教材をなぞった作品も、アプリ内だけで使う」。対象は推しの参考画像・なぞるための下絵・アプリが用意するあたり・講座の説明図やお手本に加え、それらをなぞった作品とする。教材の画素を作品PNGから除くだけでは、この指定を満たさない。

- 教材そのものと、教材をなぞった作品のPNGダウンロード・端末の共有を提供しない。工程の記録やコピーを別の持出し経路にしない。
- アプリ内の保存・再開・ギャラリー閲覧・任意の振り返りは残す。作品自体を削除したり、なぞり描きを禁止したりしない。
- 教材をなぞっていない本人の作品のPNG書き出しは残す設計とする。参考画像を横に表示しただけ、ヒントを読んだだけで、なぞったと自動認定しない。

**未確定**：個人用ZIPを例外とするか（D11）、なぞり描きの開始・旧作品・外部から取り込む絵の判定方法（D12）。今回の回答を、バックアップの例外や既存画像の削除への同意として扱わない。

今回はアプリコード・共有操作・バックアップ形式・保存データを変更しない。既存の機能を停止したり、教材入りの保存データを削除したりしない。

## 3. 実現できる制御と限界

アプリ自身の出力経路については、次を設計・検証できる。

- 教材そのもののダウンロード・外部共有の操作を用意しない。
- 教材をなぞった作品には、制作・作品詳細・専用画面・保存失敗時を含むすべてのPNG出力・端末共有の経路で同じ制限を適用する。
- 参考画像・下絵・見本・説明の図を、作品PNG・作品サムネイル・工程記録の画像へ合成しない。
- 教材に使う画像と、自分の作品へ加筆するための画像取込を、目的と保存先で区別する。
- 作品の書き出しと、教材を含む個人用バックアップを別の用途として表示する。
- 作品・参考画像・質問を、本人が知らないまま外部へ送らない。将来のAI送信も別の同意対象とする。

一方、Webアプリからスクリーンショット・画面録画・別端末での撮影や、配信済み画像の取り出しを完全に止めることはできない。現在は公開の静的サイト・リポジトリを使うため、配信素材を秘密にする仕組みにはなっていない。

右クリックや長押しの抑止、画像URLを見えにくくすることだけを、流出防止として扱わない。端末内保存もコピー防止ではない。「アプリが教材を共有する操作を提供しない」と「利用者がアプリ外へ持ち出すことを技術的に完全禁止する」は区別して説明する。

## 4. 画像の取り込みと出力の案

以下は**提案・未実装**。

1. 画像を使う入口では「参考・下絵として使う」と「自分の作品を取り込んで加筆する」を区別する。教材の画像を作品へ直接貼り付ける経路へ、気付かず進ませない。
2. 教材は独立した画像として端末内に保持し、本人の描画レイヤーと合成せず表示する。素材そのものの書出し・共有ボタンは付けない。
3. 作品PNGの出力・共有は、教材をなぞっていない本人の作品だけを対象とする。なぞった作品の線だけのPNGも出力しない。工程の記録は必要な画像をアプリ内に保存するが、制限対象の画像をダウンロードする入口は設けない。
4. 将来、登録する素材の用途・由来と作品への取込の有無を記録する。ただし画像の権利や本人作かをAI・ファイル名・画素から自動判定しない。
5. 旧作品のCanvasへ取り込まれた画像は、線と分離できるとは限らない。新しい用途情報を勝手に補完せず、画像を消したり既存作品を白紙化したりしない。出力時の扱いは方針決定後に設計する。

なぞって描いた線と元画像はデータとして分けるが、今回の指定ではどちらもアプリ内の利用にする。参考元の利用条件に関する既存の模写・トレースのヒントを維持し、アプリの出力方針と素材の権利条件を混同しない。

### なぞった作品を識別・保持するための設計課題

以下は**提案・未実装（D12で具体化する）**。

- なぞり描きを始める操作と教材の由来を、作品の利用範囲と一緒に記録する。単なる参考表示・下絵のプレビュー・ヒント閲覧と区別し、何を契機にアプリ内用になるかを操作前に短く説明する。線の形からAIでなぞり描きを推測しない。
- 一度なぞった作品は、下絵の非表示・解除、レイヤーの削除・統合、自由創作への切替、別作品へのコピーでも、アプリ内用の扱いを引き継ぐ。工程画像や、例外として認める場合のZIP復元でも同じ扱いを保つ。
- 旧作品や外部画像は、なぞったかを既存の画素や下絵の有無だけで判定できない。自動で出力可能とみなしたり、すべてを制限対象と決め付けたりしない。初回の扱い・本人への確認・不明時の出力方針は実装前に決め、元データを保持する。
- 保存失敗時にも制限対象のPNGを救済名目で外へ出さない。画面内の絵を保持して再試行できるようにし、許可される復旧手段はD11と合わせて決める。

これはアプリの正規の操作経路を制御する設計であり、別途取り直した画像や手動改変されたファイルまで出自を保証する仕組みではない。

## 5. バックアップをどう扱うか

個人の復元用バックアップと、他人への素材共有は用途が異なる。しかし現行のZIPには教材画像だけでなく、なぞった作品・レイヤー・サムネイルも含まれる。「なぞった作品もアプリ内だけ」という指定に対する例外を認めるかは未回答。次の二案は未決定であり、現在のZIPは変更しない。

| 案                                     | 挙動の案                                                                                                               | 影響・説明すべきこと                                                                                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| A 個人用バックアップを例外にする       | 教材・なぞった作品を含むZIPは本人の保存・復元用の例外とする。通常のPNG・共有は禁止したまま、復元後も利用範囲を維持する | 参考画像・下絵・作品を復元できるが、ZIPを渡せば画像も渡る。「アプリ内だけ」には個人用バックアップの例外があると明示する                           |
| B 例外を設けず、対象の外部出力を止める | 教材となぞった作品を、サムネイル・レイヤー・工程画像・復元可能な別表現も含めて外へ出す保存ファイルから除く             | 対象作品を外部バックアップできない。全データの復元とは案内せず、参照・件数・表示名・関連メモの扱いを設計し直す。既存データや旧ZIPを自動削除しない |

**設計上の比較**：Aは復元を優先する例外、Bは対象を外部ファイルにも出さない方式。以前Aを候補に挙げたが、今回の回答でAを採用したとは扱わない。どちらも本人の選択なしに確定しない。

Bを採用する場合、単にZIP内の画像を抜くだけでは不正な参照が残る。Characterの参考画像、対象作品とレイヤー、講座の記録などとの整合を取り、復元できないものを出力・復元前に表示する。元のなぞった作品を外部から再取り込みする手順を、制限の代わりとして案内しない。用途や形式が変わる場合は版・検証・互換性を含めて実装する。教材入りの旧バックアップが存在する事実も変わらない。

## 6. 教材と作品の利用条件

**指定**：教材そのものと、教材をなぞった作品をアプリ内だけで使う方針を設計へ反映する。

現在のあたり素材は[出典と条件](GUIDE_ASSETS.md)を記録している。アプリが教材の共有操作を設けないことと、配布元が認めている利用を法的・技術的に変更することは別。素材の利用条件や必要な出典表示を削らない。

原則は、教材そのもの・教材をなぞった作品・それ以外の本人の作品を区別する。教材やなぞった作品が、コピーや下絵解除によって自動で出力可能になる設計にしない。今回対象範囲が確定したが、具体的な識別方法・移行・バックアップの例外は別に設計してから実装する。

## 7. 方針決定後の完成条件

以下は今後のテスト項目で、今回の実装・テスト結果ではない。

- 教材画像に目立つ色・模様を用いたテストで、本人の線だけの作品PNG・サムネイル・工程記録へ教材の画素が混ざらない。
- 制作画面とギャラリー詳細で同じ出力制御を使い、片方だけから教材入り画像を出せない。
- 教材をなぞった作品は、教材の画素が入っていないPNGも取得・端末共有できない。通常／専用画面、保存失敗時、コピー、工程記録でも迂回できず、アプリ内の保存・再開・閲覧はできる。
- 教材を選ぶ入口から作品Canvasへ直接描き込まず、下絵として使える。自分の作品を取り込む経路は対象範囲の判断に合わせる。
- コピー・レイヤー・保存再開・画像取込後も、素材用途と作品の利用範囲を保つ。教材をなぞっていない本人の作品はPNG出力でき、旧作品・不明な出自はD12に従って扱い、内容を破壊しない。
- AならZIPへ何が入るかを明示し、Bなら教材なしの復元と参照の整合を検証する。いずれも元データ・旧ZIP・既存の復元経路を保護する。
- ネットワークの観察で、教材や本人の画像の無断送信がないことを確認する。
- スクリーンショットや配信画像の取得を完全禁止できたという誤った案内をしない。
