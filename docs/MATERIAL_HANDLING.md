# 教材をアプリ外で共有しないための整理

作成日：2026-10-29。照合対象：`5de4ff8`。**新しい要望の整理・設計案。制限を実装済みではない。**

## 1. 指定された方針と確認待ちの範囲

**指定**：「基本的に、ユーザーが教材として使用するものをアプリ外で共有しないようにしたい」。

**提案**：対象を推しの参考画像・なぞるための下絵・アプリが用意するあたり・講座の説明図やお手本とする。本人が描いた作品とは分け、教材そのものを共有するためのボタンやファイル出力は用意しない。

**確認待ち**：本人が描いた作品のPNG・共有を残すか、教材をなぞった作品もアプリ内だけにするか。対象範囲について確認を依頼している。回答が届くまでは前者を検討案とし、同意済みとは扱わない。個人用の教材入りバックアップを認めるかは、さらに別の判断事項。

今回はアプリコード・共有操作・バックアップ形式・保存データを変更しない。既存の機能を停止したり、教材入りの保存データを削除したりしない。

## 3. 実現できる制御と限界

アプリ自身の出力経路については、次を設計・検証できる。

- 教材そのもののダウンロード・外部共有の操作を用意しない。
- 参考画像・下絵・見本・説明の図を、作品PNG・作品サムネイル・工程記録の画像へ合成しない。
- 教材に使う画像と、自分の作品へ加筆するための画像取込を、目的と保存先で区別する。
- 作品の書き出しと、教材を含む個人用バックアップを別の用途として表示する。
- 作品・参考画像・質問を、本人が知らないまま外部へ送らない。将来のAI送信も別の同意対象とする。

一方、Webアプリからスクリーンショット・画面録画・別端末での撮影や、配信済み画像の取り出しを完全に止めることはできない。現在は公開の静的サイト・リポジトリを使うため、配信素材を秘密にする仕組みにはなっていない。

右クリックや長押しの抑止、画像URLを見えにくくすることだけを、流出防止として扱わない。端末内保存もコピー防止ではない。「アプリが教材を共有する操作を提供しない」と「利用者がアプリ外へ持ち出すことを技術的に完全禁止する」は区別して説明する。

## 4. 画像の取り込みと出力の案

以下は**提案・未実装**。

1. 画像を使う入口では「参考・下絵として使う」と「自分の作品を取り込んで加筆する」を区別する。教材の画像を作品へ直接貼り付ける経路へ、気付かず進ませない。
2. 教材は独立した画像として端末内に保持し、本人の描画レイヤーと合成せず表示する。素材そのものの書出し・共有ボタンは付けない。
3. 作品PNGの出力・共有は、採用した範囲の本人の作品だけを対象とする。見本の図や参考画像・下絵を含めず、制作画面・作品詳細・工程の記録で同じ原則を使う。
4. 将来、登録する素材の用途・由来と作品への取込の有無を記録する。ただし画像の権利や本人作かをAI・ファイル名・画素から自動判定しない。
5. 旧作品のCanvasへ取り込まれた画像は、線と分離できるとは限らない。新しい用途情報を勝手に補完せず、画像を消したり既存作品を白紙化したりしない。出力時の扱いは方針決定後に設計する。

なぞって描いた線は、元の画像ファイルそのものとは別に扱う。ただし、元画像をPNGへ入れなければその作品の公開条件が自動的に満たされる、とは案内しない。参考元の利用条件に関する既存の模写・トレースのヒントを維持する。なぞった作品の出力を残すかは確認待ち。

## 5. バックアップをどう扱うか

個人の復元用バックアップと、他人への素材共有は用途が異なる。しかし現行のZIPには実際に教材画像が含まれるので、扱いを明示する必要がある。次の二案は未決定であり、現在のZIPは変更しない。

| 案                               | 挙動の案                                                                                                  | 影響・説明すべきこと                                                                                                                       |
| -------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| A 個人用バックアップを例外にする | 通常の作品出力には教材を入れない。教材入りZIPは本人の保存・復元用として明示し、教材の共有用操作にはしない | 参考画像・下絵も復元できる。ZIPを他人に渡せば画像も渡るため、教材の持出しを防止したとは言えない                                            |
| B 教材のファイル出力も対象にする | 外へ出す保存ファイルには教材画像を入れず、復元時に必要なら本人が再登録する方式を設計する                  | 今の「全データバックアップ」と同じではない。画像なしの復元、参照の整合、表示名、旧ZIPの読込を設計し直す。既存データや旧ZIPを自動削除しない |

**Codexの提案**：データ消失を避けるため、まずAを候補として本人用バックアップの扱いを確認する。「外部ファイルにも一切出さない」が目的であればBを選ぶ。どちらも本人の選択なしに確定しない。

Bを採用する場合、単にZIP内の画像を抜くだけでは不正な参照が残る。Characterの参考画像、作品の下絵、講座の記録などとの整合を取り、欠けるものを復元前に表示する。用途や形式が変わる場合は版・検証・互換性を含めて実装する。教材入りの旧バックアップが存在する事実も変わらない。

## 6. 教材と作品の利用条件

**指定**：ユーザーが教材として使用するものを基本的にアプリ外で共有しない方針を設計へ追加する。

現在のあたり素材は[出典と条件](GUIDE_ASSETS.md)を記録している。アプリが教材の共有操作を設けないことと、配布元が認めている利用を法的・技術的に変更することは別。素材の利用条件や必要な出典表示を削らない。

原則は、教材の利用と本人の制作物の扱いを分ける。教材として登録した画像が、後から「本人の作品」として自動で出力可能になる設計にしない。本人の作品・トレース作品まで出力を制限する場合は、対象と影響を説明してから実装する。

## 7. 方針決定後の完成条件

以下は今後のテスト項目で、今回の実装・テスト結果ではない。

- 教材画像に目立つ色・模様を用いたテストで、本人の線だけの作品PNG・サムネイル・工程記録へ教材の画素が混ざらない。
- 制作画面とギャラリー詳細で同じ出力制御を使い、片方だけから教材入り画像を出せない。
- 教材を選ぶ入口から作品Canvasへ直接描き込まず、下絵として使える。自分の作品を取り込む経路は対象範囲の判断に合わせる。
- コピー・レイヤー・保存再開・画像取込後も、素材用途と作品の関係を保ち、旧作品の内容を破壊しない。
- AならZIPへ何が入るかを明示し、Bなら教材なしの復元と参照の整合を検証する。いずれも元データ・旧ZIP・既存の復元経路を保護する。
- ネットワークの観察で、教材や本人の画像の無断送信がないことを確認する。
- スクリーンショットや配信画像の取得を完全禁止できたという誤った案内をしない。

## 8. 今回の到達点

現行の出力経路、教材が混ざる経路、実現できる制御、Webでの限界、バックアップの判断を整理した。対象範囲とバックアップの扱いは確認待ち。アプリ本体・素材・共有ボタン・PNG／ZIP・DBは未変更で、共有制限の実装はまだ行っていない。
